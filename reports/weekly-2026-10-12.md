# 만나(MANNA) 주간 점검 리포트 — 2026-10-12

## 📌 요약 (한 눈에 보기)

만나(MANNA) 앱은 전반적으로 잘 구조화되어 있으며, 보안 기본기(인증 검사, 데이터 접근 제어, 비밀 키 관리)가 탄탄하게 갖춰져 있습니다. 다만 **이번 주 가장 중요한 발견은 "데이터베이스 테이블 이름 불일치"로 인한 치명적 버그**입니다. 코드에서 대화 내용을 `messages` 테이블에 저장하는데, 실제로 사용하는 코드는 `chat_messages` 테이블을 조회하고 있어서 **마음의 흐름(감정 그래프) 기능이 아무 데이터도 보여주지 못하는 상태**입니다. 또한 코드에 명시된 AI 모델명(`claude-sonnet-4-6`, `claude-opus-4-8`)이 실제로 존재하지 않는 이름일 가능성이 높아, 당장 서비스가 중단될 수 있는 위험이 있습니다. 이 두 가지는 출시·운영 관점에서 즉시 확인이 필요합니다.

---

## 🔴 즉시 해결이 필요한 문제

### 데이터베이스 테이블 이름 불일치 — 감정 그래프 기능이 작동하지 않음
- **파일 위치**: `src/app/journey/page.tsx` (약 110~113번째 줄) 및 `src/lib/chat-data.ts` (전체)
- **무슨 문제인가**: 대화 내용을 저장하는 창고(데이터베이스 테이블)의 이름이 코드마다 다릅니다. 데이터 설계 문서(`supabase/migrations/0001_init.sql`)와 실제 저장/조회 코드(`chat-data.ts`)는 `messages`라는 테이블을 사용합니다. 그런데 "마음의 흐름" 화면(`journey/page.tsx`)은 `chat_messages`라는 **존재하지 않는(또는 다른) 테이블**을 조회합니다. 추가로 `journey/page.tsx`는 `messages` 테이블에 `user_id` 컬럼이 있다고 가정하는데, 실제 설계상 `messages` 테이블에는 `user_id`가 없고 `session_id`만 있습니다.
- **어떤 피해가 생기나**: 사용자가 "마음의 흐름"(감정 변화 그래프)을 열면 항상 "아직 기록된 대화가 충분하지 않아요"라는 빈 화면만 보게 됩니다. 실제로는 대화를 많이 했더라도 그래프가 절대 나타나지 않습니다. 앱의 핵심 차별화 기능 중 하나가 완전히 먹통인 상태입니다.
- **권장 조치**: `journey/page.tsx`의 쿼리를 실제 데이터 구조에 맞게 수정해야 합니다. `chat_messages` → `messages`로 바꾸고, `user_id`로 직접 필터링하는 대신 사용자의 세션(`chat_sessions`)을 먼저 가져온 뒤 그 세션들에 속한 메시지를 조회하도록 변경해야 합니다. 개발자 확인이 반드시 필요합니다.

### 존재하지 않을 가능성이 높은 AI 모델명 하드코딩
- **파일 위치**: `src/lib/anthropic.ts` (36번째 줄, `claude-sonnet-4-6`), `scripts/weekly-review.mjs` (약 115번째 줄, `claude-opus-4-8`)
- **무슨 문제인가**: AI 응답을 만드는 Claude 모델의 이름이 코드에 직접 적혀 있습니다. 그런데 `claude-sonnet-4-6`, `claude-opus-4-8` 같은 이름은 실제 Anthropic(AI 제공사)이 제공하는 정식 모델명과 다를 가능성이 매우 높습니다(실제 모델명은 보통 `claude-sonnet-4-20250514`처럼 날짜가 붙은 형태입니다).
- **어떤 피해가 생기나**: 만약 이 모델명이 Anthropic에 존재하지 않으면, 사용자가 메시지를 보낼 때마다 AI 서버가 "그런 모델 없음" 오류를 돌려주고, 채팅이 전혀 작동하지 않습니다. 즉 **앱의 가장 핵심 기능(대화)이 완전히 멈춥니다**. 다만 환경변수(`ANTHROPIC_MODEL`)로 덮어쓸 수 있게 되어 있어서, 실제 운영 환경에 올바른 모델명을 설정해 두었다면 괜찮을 수도 있습니다.
- **권장 조치**: 지금 실제 서비스(Netlify)에 `ANTHROPIC_MODEL` 환경변수가 올바른 값으로 설정되어 있는지 **즉시 확인**하세요. 설정되어 있지 않다면, 코드의 기본값을 Anthropic이 실제 제공하는 정확한 모델명으로 수정해야 합니다.

### 메모리 기능이 저장하는 테이블의 보안 설정이 위험함
- **파일 위치**: `supabase/001_user_memories.sql` (전체), `src/lib/manna-memory.ts`
- **무슨 문제인가**: 장기 기억(사용자의 반복되는 고민, 감정 등을 기억하는 기능)을 저장하는 `user_memories` 테이블은, 사용자 본인만 쓰기(INSERT/UPDATE)가 가능하도록 보안(RLS)이 설정되어 있습니다. 그런데 실제로 메모리를 저장하는 코드(`updateUserMemory`)는 **일반 사용자 권한(anon key)으로 로그인한 상태**에서 서버가 대신 저장을 시도합니다. 서버 코드의 Supabase 클라이언트는 쿠키 기반 사용자 세션을 쓰므로 본인 데이터 저장은 가능하지만, 매우 민감한 개인 정보(반복되는 심리적 어려움, 감정 상태)를 담는 테이블이라 각별한 주의가 필요합니다.
- **어떤 피해가 생기나**: 현재 로직 자체는 작동할 수 있으나, 사용자의 가장 내밀한 심리 데이터를 다루는 만큼, 접근 제어가 조금만 느슨해져도 개인정보 유출 사고로 이어질 수 있습니다.
- **권장 조치**: `user_memories` 테이블의 RLS 정책이 실제로 활성화되어 있고 본인만 접근 가능한지 Supabase 콘솔에서 재확인하세요. 또한 이 테이블이 아직 생성되지 않았다면 메모리 기능은 조용히 실패하도록 설계되어 있으니, 운영 DB에 테이블이 존재하는지도 확인이 필요합니다.

## 🟡 가까운 시일 내에 개선이 필요한 부분

### 중복된 메모리 코드 파일 (혼란과 유지보수 비용)
- **파일 위치**: `src/lib/manna-memory.ts` 와 `src/lib/selah-memory.ts`
- **무슨 문제인가**: 두 파일의 내용이 거의 100% 동일합니다. 과거 SELAH 앱에서 MANNA로 이름을 바꾸면서 기존 파일을 남겨둔 것으로 보입니다. 실제 사용되는 것은 `manna-memory.ts`이고, `selah-memory.ts`는 어디에서도 불러오지 않는 죽은 파일입니다.
- **어떤 피해가 생기나**: 당장 오류는 없지만, 나중에 메모리 로직을 고칠 때 둘 중 하나만 수정하면 혼란이 생기고, 개발자가 "어느 파일이 진짜인지" 헷갈려 버그를 만들 수 있습니다.
- **권장 조치**: 사용되지 않는 `src/lib/selah-memory.ts` 파일을 삭제하세요.

### 사용되지 않는 중복 설치 안내 컴포넌트
- **파일 위치**: `src/components/AddToHomePrompt.tsx`
- **무슨 문제인가**: 앱 홈 화면 추가를 안내하는 컴포넌트가 두 개(`AddToHomePrompt.tsx`, `install-prompt.tsx`) 있습니다. 실제 레이아웃(`layout.tsx`)에서는 `InstallPrompt`만 사용하고, `AddToHomePrompt`는 아무 곳에서도 불러오지 않습니다.
- **어떤 피해가 생기나**: 역시 당장의 오류는 없으나, 불필요한 코드가 쌓이면 유지보수가 어려워집니다.
- **권장 조치**: 사용되지 않는 `AddToHomePrompt.tsx`를 삭제하거나, 둘 중 하나로 통일하세요.

### 요금(rate limit) 제한이 서버 재시작 시 초기화됨
- **파일 위치**: `src/lib/rate-limit.ts` (전체)
- **무슨 문제인가**: 한 사용자가 1분에 20번까지만 AI에게 메시지를 보낼 수 있도록 제한하는 장치가 있는데, 이 제한 기록이 서버 메모리에만 저장됩니다. Netlify 같은 서버리스 환경에서는 서버가 자주 새로 뜨고(cold start), 여러 서버 인스턴스가 동시에 돌기 때문에, 이 제한이 제대로 작동하지 않을 수 있습니다.
- **어떤 피해가 생기나**: 악의적인 사용자가 AI 호출을 폭주시켜 **후원금으로 운영되는 API 비용을 급격히 늘릴 수 있습니다**. 코드 주석에도 이 한계가 명시되어 있습니다.
- **권장 조치**: 사용자가 늘어나거나 비용이 걱정되면, Upstash Redis 같은 외부 저장소를 이용한 제대로 된 요금 제한으로 교체하는 것을 검토하세요. 당장은 급하지 않지만 비용 폭탄 방지를 위해 염두에 두어야 합니다.

### 크론 알림이 1분에 수백 명에게 순차 발송되어 시간 초과 위험
- **파일 위치**: `src/app/api/cron/send-reminders/route.ts` (약 150~180번째 줄)
- **무슨 문제인가**: 기도 알림을 보낼 때, 대상 사용자와 기기를 하나씩 순서대로(for 반복문) 처리합니다. 알림을 받을 사람이 많아지면 한 번에 다 보내지 못하고, 서버 실행 시간 제한(Netlify Function은 보통 10~26초)에 걸려 일부 사용자는 알림을 못 받을 수 있습니다.
- **어떤 피해가 생기나**: 사용자가 많아지면 "리마인더를 켰는데 알림이 안 온다"는 불만이 생길 수 있습니다. 또한 발송 성공 후 `last_sent_at` 업데이트가 중간에 멈추면 다음 실행 때 중복 발송될 수도 있습니다.
- **권장 조치**: 사용자 규모가 커지기 전까지는 괜찮지만, 발송을 병렬 처리(`Promise.all`)하거나 배치 단위로 나누는 개선을 염두에 두세요.

## 🟢 장기적으로 개선하면 좋은 점

### 이미지는 저장되지 않아 과거 대화에서 사진이 사라짐
- **파일 위치**: `src/components/chat/chat-app.tsx` (약 200번째 줄, 주석 포함)
- **무슨 문제인가**: 사용자가 보낸 사진은 메모리에만 잠깐 보관되고 데이터베이스에 저장되지 않습니다(저장 용량 절감 목적). 코드 주석에도 의도된 설계라고 명시되어 있습니다.
- **어떤 피해가 생기나**: 사용자가 과거 대화를 다시 열면 자신이 보냈던 사진은 보이지 않고 "[사진을 보냈어요]"라는 글자만 남습니다. 사용자 입장에서는 혼란스러울 수 있습니다.
- **권장 조치**: 당장은 비용 절감 측면에서 합리적입니다. 추후 유료화 시 이미지 저장 옵션을 고려할 수 있습니다.

### PIN 잠금의 암호화 방식이 매우 약함
- **파일 위치**: `src/components/chat/pin-gate.tsx` (약 30번째 줄, `fnv1a` 함수)
- **무슨 문제인가**: 개인정보 보호용 4자리 PIN을 저장할 때 FNV-1a라는 아주 가벼운 해시(단방향 암호화)를 씁니다. 이는 쉽게 역산되거나 4자리 전수 대입(0000~9999)으로 순식간에 뚫립니다.
- **어떤 피해가 생기나**: 코드 주석에도 명시되어 있듯이 이 PIN은 "인증을 대체하지 않으며, 같은 기기를 쓰는 가족이 우연히 보는 것을 막는 용도"일 뿐입니다. 실제 보안 수준은 낮습니다.
- **권장 조치**: 의도된 용도(프라이버시 가림막)로는 충분합니다. 다만 사용자에게 "이것은 완전한 보안 잠금이 아니다"라는 점이 명확히 전달되는지 확인하면 좋습니다.

### "오늘의 한 마디"가 한국어만 제공됨
- **파일 위치**: `src/app/today/page.tsx` (약 30~70번째 줄, `KO_BANK`)
- **무슨 문제인가**: 앱은 30개 언어를 지원하는데, "오늘의 한 마디" 콘텐츠는 한국어 문장만 준비되어 있습니다. 영어 사용자도 한국어 카드를 보게 됩니다.
- **어떤 피해가 생기나**: 비한국어 사용자가 이 페이지를 열면 읽을 수 없는 한국어만 보여 어색한 경험을 합니다.
- **권장 조치**: 글로벌 앱을 지향한다면 주요 언어별 콘텐츠를 추가하는 것이 좋습니다.

## 🔒 보안 점검 결과

| 점검 항목 | 평가 | 설명 |
|-----------|------|------|
| **채팅 API 인증 검사** | ✅ 양호 | `/api/chat`에서 로그인 여부를 먼저 확인하고, 비로그인 시 401로 차단합니다. API 키 보호가 잘 되어 있습니다. |
| **AI 비밀 키(ANTHROPIC_API_KEY) 관리** | ✅ 양호 | 서버 환경변수로만 사용하고 클라이언트에 노출되지 않습니다. |
| **데이터베이스 접근 제어(RLS)** | ✅ 양호 | 모든 주요 테이블(대화, 세션, 프로필, 알림)에 행 수준 보안이 설정되어 사용자는 자기 데이터만 접근 가능합니다. |
| **크론 알림 엔드포인트 보호** | ✅ 양호 | `x-cron-secret` 헤더로만 접근 허용하고, 쿼리스트링 방식을 명시적으로 폐기했습니다(로그 유출 방지). 모범적입니다. |
| **입력값 검증 (알림 설정)** | ✅ 양호 | 시간 형식, 시간대(timezone), 메시지 길이(300자)를 서버에서 검증합니다. |
| **입력값 검증 (이미지 업로드)** | ✅ 양호 | 이미지 크기 상한(7MB)과 형식(data:image/)을 서버에서 재확인합니다. |
| **SQL 인젝션** | ✅ 양호 | Supabase 클라이언트의 파라미터 방식을 사용해 직접 SQL을 조립하지 않아 안전합니다. |
| **보안 헤더(클릭재킹, HTTPS 강제 등)** | ✅ 양호 | `next.config.mjs`에 X-Frame-Options, HSTS 등 기본 보안 헤더가 잘 설정되어 있습니다. |
| **요금 제한(비용 방어)** | ⚠️ 주의 | 메모리 기반이라 서버리스 환경에서 완전하지 않습니다. 비용 폭주 가능성이 있습니다. |
| **민감 심리 데이터(user_memories) 보호** | ⚠️ 주의 | RLS는 설정되어 있으나, 매우 민감한 데이터인 만큼 테이블 존재·정책 적용 여부를 운영 DB에서 재확인 필요. |
| **PIN 잠금 강도** | ⚠️ 주의 | 암호화가 약하나, 용도(프라이버시 가림막)상 허용 범위입니다. |
