# 만나(MANNA) 주간 점검 리포트 — 2026-08-24

## 📌 요약 (한 눈에 보기)
전체적으로 코드 완성도가 높고, 인증(로그인 검증)·데이터 접근 제어(RLS)·보안 헤더가 잘 갖춰져 있어 출시 가능한 수준입니다. 다만 **이번 주 가장 중요한 발견 두 가지**가 있습니다. 첫째, 채팅 화면에서 대화 내용을 불러오고 저장하는 데 사용하는 데이터베이스 테이블 이름이 서로 엇갈려 있어(`messages` vs `chat_messages`) **저장한 대화가 다시 열리지 않을 위험**이 있습니다. 둘째, 코드 점검 자동화 스크립트가 **존재하지 않는 AI 모델 이름**을 가리키고 있어 주간 리포트 자동 생성이 실패할 수 있습니다. 그 외에 로그인 오류 메시지가 사용자에게 영어로만 노출되는 점, 오래된 `selah-memory.ts` 잔재 등 정리할 부분이 있습니다.

## 🔴 즉시 해결이 필요한 문제

### 채팅 데이터 테이블 이름 불일치 — 저장한 대화가 사라지거나 안 열릴 위험
- **파일 위치**: `src/lib/chat-data.ts` (49번째 줄 `listMessages`, 61번째 줄 `saveMessage`)와 `src/app/journey/page.tsx` (약 108번째 줄), `src/app/chat/page.tsx` (약 55번째 줄)
- **무슨 문제인가**: 앱은 대화 메시지를 저장하는 데이터 창고(테이블)를 사용합니다. 그런데 코드마다 이 창고를 부르는 이름이 다릅니다.
  - `chat-data.ts`는 `"messages"`라는 이름을 사용합니다.
  - `journey/page.tsx`는 `"chat_messages"`라는 이름을 사용합니다.
  - 데이터베이스 설계 파일(`supabase/migrations/0001_init.sql`)에는 실제로 `messages`라는 테이블만 만들어져 있고 `chat_messages`는 없습니다.
  같은 앱 안에서 서로 다른 이름을 부르고 있어, 한쪽은 정상 작동하고 다른 한쪽은 존재하지 않는 창고를 열려다 실패합니다.
- **어떤 피해가 생기나**: "마음의 흐름(journey)" 화면은 존재하지 않는 `chat_messages` 테이블을 조회하므로 **항상 빈 화면**이 나오거나 데이터를 전혀 가져오지 못합니다. 사용자는 며칠간 대화를 나눠도 마음 그래프가 영원히 비어 있게 됩니다. 또한 `chat-data.ts`가 세션(대화방)은 `chat_sessions`에 저장하면서 메시지는 `messages`에 저장하는데, 서버 렌더링 쪽(`chat/page.tsx`)에서도 세션은 `chat_sessions`를 쓰므로 일관성 확인이 필요합니다.
- **권장 조치**: 실제로 데이터베이스에 만들어진 테이블 이름(`messages`)으로 **모든 코드를 통일**하거나, 반대로 데이터베이스에 `chat_messages` 테이블을 정식으로 추가하고 모든 코드를 그쪽으로 맞춰야 합니다. 개발팀이 어느 이름이 실제 운영 DB에 존재하는지 먼저 확인한 뒤, 한쪽으로 즉시 통일하는 것을 권장합니다. `journey/page.tsx`가 조회하는 `chat_messages`가 특히 위험합니다.

### 주간 점검 자동화 스크립트가 존재하지 않는 AI 모델을 호출
- **파일 위치**: `scripts/weekly-review.mjs` (약 116번째 줄 `model: 'claude-opus-4-8'`)
- **무슨 문제인가**: 이 리포트를 자동 생성하는 스크립트가 Claude AI에게 `claude-opus-4-8`이라는 모델을 사용하라고 요청합니다. 그러나 이 이름은 실제 존재하지 않는(오타로 추정되는) 모델명입니다. 앱 본체(`src/lib/anthropic.ts`)는 `claude-sonnet-4-6`을 정상적으로 사용하고 있습니다.
- **어떤 피해가 생기나**: 주간 코드 점검 리포트가 자동으로 생성되지 않고 **오류로 중단**됩니다. 운영 담당자가 매주 코드 상태를 자동으로 점검받지 못하게 됩니다.
- **권장 조치**: `scripts/weekly-review.mjs`의 모델 이름을 실제 존재하는 모델(예: `claude-sonnet-4-6` 또는 실제 사용 가능한 Opus 모델명)로 수정하세요. 간단한 한 줄 수정입니다.

## 🟡 가까운 시일 내에 개선이 필요한 부분

### 로그인 오류 메시지가 영어로만 노출됨
- **파일 위치**: `src/app/login/page.tsx` (약 90번째 줄, 105번째 줄 등 `setError(error.message)`)
- **무슨 문제인가**: 로그인·회원가입 실패 시 Supabase(인증 서비스)가 돌려주는 오류 메시지를 그대로 화면에 보여줍니다. 이 메시지는 대부분 영어입니다(예: "Invalid login credentials"). 앱은 7개 언어를 지원하고 한국어 사용자가 주 대상인데, 정작 오류 상황에서 영어가 튀어나옵니다.
- **어떤 피해가 생기나**: 한국어 사용자(특히 시니어 사용자)가 로그인 실패 이유를 이해하지 못해 이탈하거나 문의가 늘어납니다.
- **권장 조치**: 자주 발생하는 인증 오류(잘못된 비밀번호, 이미 가입된 이메일 등)를 사용자 언어로 번역해 매핑하는 처리를 추가하세요.

### 중복된 메모리 코드 파일(`selah-memory.ts`)이 방치되어 있음
- **파일 위치**: `src/lib/selah-memory.ts` (파일 전체)
- **무슨 문제인가**: `src/lib/manna-memory.ts`와 거의 100% 동일한 내용의 `selah-memory.ts`가 함께 존재합니다. 실제로 채팅 API(`src/app/api/chat/route.ts`)는 `manna-memory.ts`만 사용하므로, `selah-memory.ts`는 아무 데서도 쓰이지 않는 죽은 코드입니다.
- **어떤 피해가 생기나**: 당장 오류는 없으나, 나중에 메모리 로직을 수정할 때 어느 파일이 진짜인지 헷갈려 한쪽만 고치는 실수를 유발합니다. 유지보수 혼란과 잠재적 버그의 씨앗입니다.
- **권장 조치**: 사용되지 않는 `selah-memory.ts`를 삭제하세요.

### 사용하지 않는 컴포넌트(`AddToHomePrompt.tsx`)와 설치 안내 중복
- **파일 위치**: `src/components/AddToHomePrompt.tsx` (파일 전체)
- **무슨 문제인가**: 홈 화면 추가 안내 팝업이 `AddToHomePrompt.tsx`와 `install-prompt.tsx` 두 개로 존재합니다. 실제 레이아웃(`src/app/layout.tsx`)에서는 `InstallPrompt`만 사용하고 `AddToHomePrompt`는 어디에도 연결되어 있지 않습니다. 또한 `AddToHomePrompt`는 오래된 저장 키(`selah_add_to_home_prompt_closed_at`)를 씁니다.
- **어떤 피해가 생기나**: 죽은 코드로 인한 혼란. 향후 두 파일을 모두 활성화하면 사용자에게 설치 팝업이 두 번 뜰 수 있습니다.
- **권장 조치**: 사용하지 않는 `AddToHomePrompt.tsx`를 삭제하세요.

### 채팅 메시지에서 "즐겨찾기/공유" 기능이 세션 정보를 못 받음
- **파일 위치**: `src/components/chat/chat-window.tsx` (약 168번째 줄 `<MessageBubble>` 렌더링 부분)
- **무슨 문제인가**: 메시지 말풍선(`MessageBubble`)은 즐겨찾기 저장 시 어느 대화방(sessionId)의 메시지인지 기록하도록 설계되어 있으나, `chat-window.tsx`에서 `sessionId`를 넘겨주지 않아 항상 `null`로 저장됩니다.
- **어떤 피해가 생기나**: 사이드바 "즐겨찾기" 탭에서 즐겨찾기한 글을 눌러도 원래 대화방으로 이동하지 못합니다(코드상 `if (f.sessionId) onSelect(...)` 조건이 항상 거짓). 기능이 반쪽만 작동합니다.
- **권장 조치**: `chat-window.tsx`에서 현재 활성 세션 ID를 `MessageBubble`에 전달하도록 연결하세요.

### 대화 내역이 사용자 필터 없이 조회됨(방어적 확인 필요)
- **파일 위치**: `src/lib/chat-data.ts` (약 10번째 줄 `listSessions`), `src/app/chat/page.tsx` (약 56번째 줄)
- **무슨 문제인가**: 세션 목록을 가져올 때 `user_id`로 명시적으로 걸러내지 않고 전체를 조회합니다. 데이터베이스의 접근 제어(RLS)가 자기 데이터만 보이도록 막아주기 때문에 실제로는 안전하지만, 코드만 보면 "왜 필터가 없지?" 하는 불안 요소가 됩니다.
- **어떤 피해가 생기나**: 만약 향후 실수로 RLS 정책이 비활성화되면, 즉시 다른 사용자의 대화 목록이 노출될 수 있습니다. RLS가 유일한 안전장치인 상태입니다.
- **권장 조치**: 안전을 이중화하기 위해 조회 쿼리에도 `.eq("user_id", ...)` 필터를 명시적으로 추가할 것을 권장합니다.

## 🟢 장기적으로 개선하면 좋은 점

### 요청 제한(rate limit)이 서버 인스턴스별로만 작동
- **파일 위치**: `src/lib/rate-limit.ts` (파일 전체)
- **무슨 문제인가**: 한 사용자가 1분에 20번까지만 AI를 호출하도록 제한하는데, 이 제한은 각 서버 인스턴스 메모리에만 저장됩니다. Netlify 같은 서버리스 환경에서는 요청마다 다른 인스턴스로 흩어질 수 있어 실제 제한이 느슨해집니다.
- **어떤 피해가 생기나**: 악의적 사용자가 제한을 우회해 기부금으로 운영되는 AI 비용을 과다 발생시킬 수 있습니다. 지금은 소규모라 큰 문제는 아닙니다.
- **권장 조치**: 사용자 규모가 커지면 Redis 등 공유 저장소 기반 제한으로 교체하세요(코드 주석에도 이미 언급됨).

### "오늘의 한 마디"가 한국어 문구만 존재
- **파일 위치**: `src/app/today/page.tsx` (약 30번째 줄 `KO_BANK`)
- **무슨 문제인가**: 7개 언어를 지원하는 앱이지만, 오늘의 한 마디 카드는 한국어 문구 은행(`KO_BANK`)만 있습니다. 다른 언어 사용자도 한국어 문구를 보게 됩니다.
- **어떤 피해가 생기나**: 비한국어 사용자에게 이질감을 줍니다. 심각한 오류는 아닙니다.
- **권장 조치**: 주요 지원 언어별 문구 은행을 추가하세요.

### 이미지가 데이터베이스에 저장되지 않음(설계상 의도)
- **파일 위치**: `src/components/chat/chat-app.tsx` (약 220번째 줄 부근 주석)
- **무슨 문제인가**: 사용자가 보낸 사진은 화면에만 잠시 보이고 저장되지 않습니다. 저장 공간 절약을 위한 의도적 설계입니다.
- **어떤 피해가 생기나**: 대화를 다시 열면 사진은 사라지고 "[사진을 보냈어요]" 표시만 남습니다. 사용자가 혼란스러울 수 있습니다.
- **권장 조치**: 사용자에게 "사진은 저장되지 않습니다"를 안내하거나, 향후 이미지 저장 기능 도입을 검토하세요.

## 🔒 보안 점검 결과

- **인증(로그인 검증)**: ✅ 양호 — 채팅 API가 로그인한 사용자만 접근하도록 `getUser()`로 검증하며(`src/app/api/chat/route.ts` 47~62줄), 미들웨어(`src/lib/supabase/middleware.ts`)가 `/chat` 경로를 보호합니다.
- **API 키 관리**: ✅ 양호 — Anthropic API 키는 서버(`process.env.ANTHROPIC_API_KEY`)에서만 사용되고 클라이언트로 노출되지 않습니다. Supabase 익명 키만 공개되며 이는 정상입니다.
- **데이터베이스 접근 제어(RLS)**: ✅ 양호 — 모든 주요 테이블(profiles, chat_sessions, messages, user_memories, push_subscriptions, prayer_reminders)에 행 수준 보안이 적용되어 각 사용자가 자기 데이터만 접근 가능합니다.
- **입력값 검증**: ⚠️ 주의 — 이미지 크기 제한(7MB), 리마인더 시간·타임존 검증은 잘 되어 있으나, 채팅 메시지 내용 자체의 길이 제한이 없습니다. 매우 긴 텍스트를 반복 전송하면 비용이 증가할 수 있습니다(rate limit이 일부 방어).
- **크론(예약 작업) 보안**: ✅ 양호 — 리마인더 발송 크론(`src/app/api/cron/send-reminders/route.ts`)이 비밀 키를 헤더로만 받도록 하고, 쿼리스트링 방식을 제거해 로그 유출을 막았습니다.
- **보안 헤더**: ✅ 양호 — 클릭재킹 방지(X-Frame-Options), HTTPS 강제(HSTS) 등 기본 보안 헤더가 `next.config.mjs`에 설정되어 있습니다.
- **PIN 잠금**: ⚠️ 주의 — 클라이언트 PIN 잠금(`pin-gate.tsx`)이 약한 해시(FNV-1a)를 사용합니다. 다만 이는 인증 대체가 아닌 "어깨너머 보기 방지"용 프라이버시 기능이라 명시되어 있어 용도 대비 적정합니다.
